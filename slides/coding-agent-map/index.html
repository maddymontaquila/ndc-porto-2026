The gap

Your agent can read the repo.
Can it see the app?

SOURCE

Files and instructions

Useful context about code. Not the live shape and behavior of a distributed app.

RUNNING APP

Resources and relationships

The services, dependencies and signals you need to understand the whole system.

Make the distinction carefully: repository instructions help, but they are a manually maintained description. The running app has its own topology and behavior. Today is about giving the coding agent a structured path to that context.

Copy-paste is not a workflow

WITHOUT THE APP MAP

Find a service. Start it alone. Copy logs. Explain what you already know. Repeat.

→

WITH ASPIRE

Work against the app model, run the stack, and inspect what actually happened.

Less context wrangling. More time on the change you meant to make.

This is the pain from the session abstract. Acknowledge that you can still inspect an individual service when that is the right thing to do. Aspire makes the whole app available as the context, rather than forcing you to reconstruct it manually.

Keep the point grounded: the app map tells you what the pieces are and how they relate. Logs, traces and metrics tell you what they are doing. Aspire 17's resource pane lets you keep the resources you are investigating in view as you navigate those signals.

A useful agent loop

01OrientRead the app map
02ActMake the requested change
03ObserveRun the app and inspect signals
04VerifyTest the intended behavior

Then loop again—with evidence, not a guess.

The loop is the practical payoff. The agent learns the topology, makes a scoped change, operates the whole app and checks the result. The human still defines the task and decides whether the change is acceptable.

Context is not control

GIVE CONTEXT

App model + signals

Let the agent understand resources, relationships and observed behavior.

KEEP CONTROL

Permissions + review

Use your agent’s permissions, tests and human review to govern changes.

Structured access makes the work clearer. It does not replace your security model.

Be explicit that Aspire context and tools are not a security boundary. Follow the agent platform’s permissions, protect secrets, review proposed edits, and decide which commands and actions are permitted.

No Markdown map to babysit

MODEL

AppHost

Describe resources and references in code.

RUNTIME

Aspire

Run the app as a connected system.

Dashboard + CLI

Keep architecture where it belongs: with the app, not in a second description of it.

Avoid saying documentation has no value. The point is not to ban Markdown; it is to avoid relying on a hand-maintained file as the only description of a changing application. The AppHost is executable context, and the dashboard and CLI show live state.
